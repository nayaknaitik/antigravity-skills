# Product Discovery Strategy

**Goal**: Understand the complete breadth of the product across 50 critical dimensions before writing any requirements.

**The 50 Dimensions**:
Ensure decisions are made for all relevant dimensions:
1. Vision, 2. Problem Statement, 3. Target Users, 4. Stakeholders, 5. Business Goals, 6. Success Metrics, 7. Existing Alternatives, 8. Competitive Landscape, 9. User Personas, 10. User Journey, 11. User Pain Points, 12. Core Features, 13. Feature Prioritization, 14. MVP Scope, 15. Out-of-Scope Features, 16. Business Rules, 17. Functional Requirements, 18. Non-functional Requirements, 19. Security Requirements, 20. Privacy Requirements, 21. Compliance Requirements, 22. Authentication, 23. Authorization, 24. Roles & Permissions, 25. Data Requirements, 26. APIs, 27. Integrations, 28. Notifications, 29. Reporting, 30. Analytics, 31. Search, 32. AI Features, 33. Offline Support, 34. Scalability, 35. Availability, 36. Reliability, 37. Performance, 38. Observability, 39. Logging, 40. Monitoring, 41. Audit Logs, 42. Error Handling, 43. Edge Cases, 44. Failure Scenarios, 45. Constraints, 46. Risks, 47. Assumptions, 48. Future Scope, 49. Technical Constraints, 50. Deployment Considerations.

**Action**: Evaluate which of these dimensions lack concrete decisions based on the user's initial input, and transition to questioning.
